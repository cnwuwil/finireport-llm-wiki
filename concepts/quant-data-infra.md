# 量化数据基础设施

量化策略的基础：没有稳定、干净、及时的数据，因子计算、回测、实盘均无从谈起。

## 数据来源三层

| 层级 | 代表 | 优势 | 适用场景 |
|------|------|------|----------|
| 交易所直连 / Level-2 | 上交所、深交所 | 延迟最低、最全 | 大型私募/券商实盘 |
| 第三方数据商 | Wind、聚宽、米筐、Tushare | 覆盖全、接口友好 | 研究阶段首选 |
| 开源/免费 | Tushare、AkShare | 零成本 | 学习、小规模回测 |

**业内常见组合**
- 小团队：聚宽/米筐回测 + 券商实盘行情
- 中型私募：Wind 研究 + 券商 Level-2 实盘（双源校验）
- 大型机构：交易所 Level-2 + 自建清洗存储

## 数据频率选择

```
tick → 高频策略、微观结构分析、精细执行
分钟线 → 中频因子、执行分析、日内风控
日频 → 多因子、指增、组合管理（覆盖大多数策略）
```

**原则**：先把日频数据做准、做全，再考虑上分钟/tick。指增和多因子绝大多数以日频为主。

## 存储分层架构

### 热数据（在线，近 1～2 年）
- **关系型**（MySQL / PostgreSQL）：日频因子表、组合权重、配置表——结构化、强一致、易关联查询
- **时序/列存**（ClickHouse / DolphinDB / QuestDB）：行情、分钟线、tick——按「日期+标的」分区，压缩比高，范围查询快

### 温数据（分区按需加载）
- 更早历史或分钟级数据，用分区表避免单机内存爆掉

### 冷数据（归档，3～5 年以上）
- **对象存储（OSS/S3）+ Parquet**：成本最低，用 Spark/Pandas 按需读取；常用于长期回测和合规留档

## 关键规范（坑点）

### 时间戳
统一用**交易所时间**或 UTC，不要混用「自然日 vs 交易日」「Bar 时间 vs 收到时间」，否则容易引入前视偏差或信号错位。

### 复权与合约
- 股票：明确前复权 vs 后复权，全库统一
- 期货：换月连续合约要有映射表
- 指数：成分变更要有版本表，确保回测可复现

### 数据版本（point-in-time）
因子和行情最好带「生成时间 / 版本号」，回测时只能用「当时可得」的数据，防止未来信息泄漏。
